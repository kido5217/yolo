# v0.4.0 — Design

Date: 2026-08-24 · Status: approved (user, 2026-08-24, in chat: "LGTM")
Supersedes: the porting *policy* of the v1 design (2026-08-17, "contract-
faithful, layered port") and of root core principles 2–3 as worded before
v0.4.0. The v1 design remains the historical record and the wire-contract

This spec records a direction change: purpose + porting policy. No code.

## 1. Background

The project's original purpose was to test the capabilities of
**Qwen3.8-27B** on a single RTX 5090 behind `https://ai.kido.ws/v1`, using a
faithful Go port of [opencode](https://github.com/anomalyco/opencode)
**v1.18.18** as the harness. That goal is **complete**: local Qwen 3.8 has
been tested, and it is stable and optimized (v0.3.0 closed the entire
deferred backlog; the v0.3.0 tree is the stable baseline).

## 2. Policy changes (v0.4.0)

### 2.1 New purpose

From v0.4.0, the project is used to **test various LLM harnesses and
frameworks**: yolo drives and evaluates *other* harnesses (e.g. opencode,
codex-class CLIs). The existing yolo TUI + core-server binary remains the
stable baseline product — it is both the first harness under comparison and
the foundation the harness-testing capability builds on.

The harness-testing subsystem itself is **out of scope for this spec**; it
gets its own (architectural) spec when it is built.

### 2.2 Reference, not contract

opencode v1.18.18 is a **reference** for how things should be done, not a
binding contract:

- The mirrored legacy REST paths / JSON shapes / SSE event set **stays**, so
  the baseline remains verifiable against opencode's OpenAPI contract.
- yolo **may deviate from upstream** — wire shapes, behavior, or pinned text —
  **on explicit user instruction**. Every such deviation is logged in
  `docs/superpowers/DEVIATIONS.md` with severity (append-only discipline
  unchanged).
- The standing baseline wire deviation (`x-yolo-directory`) is unchanged.
- **Zero telemetry (principle 1) is unchanged** — non-negotiable.

This restates root core principle 2:

> **Reference, not contract.** opencode v1.18.18 is a *reference* for how
> things should be done, not a binding contract. The legacy REST paths/JSON
> shapes and the legacy SSE event set remain mirrored so the baseline stays
> verifiable against opencode's OpenAPI contract, but yolo may deviate from
> upstream (wire shapes, behavior, pinned text) on explicit user instruction —
> every such deviation is logged in `docs/superpowers/DEVIATIONS.md` with
> severity. Standing baseline deviation: the scoping header is
> `x-yolo-directory` (upstream: `x-opencode-directory`).

### 2.3 Pins are change gates, not upstream locks

The 21 sha256-pinned files — 14 `internal/session/prompt/*.txt`
(`TestPromptFilesPinned`, `internal/session/prompt_test.go`) and 7
`internal/tool/desc/*.txt` (per-tool `TestDescPinned`) — record **current
intended content**, not an upstream lock:

- Pinned text may change as part of normal work (no specific upstream-
  deviation instruction required).
- An intentional change **re-baselines the sha256 pin in the same commit** —
  no dangling pins; the tests still catch accidental or unintended edits.

This restates root core principle 3:

> **Pins are change gates, not upstream locks.** The 14 session prompt files
> and all tool `desc/*.txt` files are guarded by sha256 pins in tests. The
> pins record current intended content, not an upstream lock: pinned text may
> change in normal work, and an intentional change re-baselines the sha256
> pin in the same commit. Never leave a pin dangling.

## 3. Scope of v0.4.0

Documentation only:

2. Live docs restated to the new policy: root `AGENTS.md` (Project paragraph,

   `docs/superpowers/PROGRESS.md` (verified fact appended).

## 4. Explicitly out of scope

- The harness-testing subsystem (driving/evaluating other harnesses) — a
  future architectural spec.
- Zero telemetry — unchanged, non-negotiable.
- The mirrored REST/SSE baseline — unchanged.
- Historical dated specs / plans / reviews / archives — immutable records,
  not restated.
- The v1 spec's porting-strategy wording — historical; this spec supersedes
  the *policy*, not the record.
