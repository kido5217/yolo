## 1. Scope & release slicing

**0.2.0 = MINOR** (new features: version wiring, logging; the fixes ride along).
Three streams, one release, one later implementation plan.

| Stream | Content |
|---|---|
| Version wiring + just | ldflags/`git describe` version, VCS-stamped `yolo version`, `-v`/`--version` (absorbs `cli-4`), `justfile` as the single entry point for all scripts (§2) |
| Logging rework | slog-based `internal/log` reimplementation, levels, new log points; absorbs `security-5` (CWE-117) and `troubleshoot-2` (nil `Deps.Log`) (§3) |
| Backlog fixes | 12 fixes: all P0/P1 from the v0.1.2 deferred set + the 2 P2 hot-path performance items (§4) |

**Ordering inside 0.2.0:** §4 item ④ (API error drain) before ⑦ (overflow
classification, which consumes the decoded error); the logging stream after ⑧/⑨
where files overlap; ⑩/⑪ last (hot path, largest regression risk; wave-13
benchmarks as baselines). Every fix is its own gate-green commit.

**Out of 0.2.0 → 0.3.0 slice:** all remaining v0.1.2 deferred findings and the
16-entry refactoring backlog — §5. Carried in an updated `DEFERRED.md`
(per-item `fixed in 0.2.0` / `0.3.0 slice` annotations) during implementation.

**Release flow:** task branch → commits → PR → user merge (no direct `main`
commits); `v0.2.0` tag ONLY with explicit user go-ahead (root rule).

## 2. Version wiring + just migration

- One unexported package-level var in `cmd/yolo`: `version = "0.0.0-dev"`.
  `ldflags -X main.version=...` targets it; no new package or import path.
- `yolo version` prints:
  ```
  yolo 0.2.0
  commit abc1234d
  built  2026-08-22T10:00:00Z
  ```
  Line 1 always (the ldflags-injected `version`). Lines 2–3 come from Go's
  automatic VCS stamping (`debug.ReadBuildInfo()` → `Settings`, keys
  `vcs.revision` / `vcs.time`) and are omitted when absent (e.g.
  `GOFLAGS=-buildvcs=false`).
- New `justfile` at repo root — the single entry point for all scripts:
  ```just
  version := `git describe --tags --always --dirty || echo 0.0.0-dev`

  build:
      go build -ldflags "-X main.version={{version}}" -o yolo ./cmd/yolo

  e2e-live:
      scripts/e2e-live.sh
  ```
  Simple things are native recipes (`build`); complex scripts stay as bash
  files and are invoked only through just (`e2e-live` passes through — the
  script keeps reading `KIDO_API_KEY` / `KIDO_BASE_URL` / `E2E_TIMEOUT`).
  New tooling in 0.2.0+ lands in the justfile, not in new `.sh` files.
  `--always` covers untagged checkouts (short SHA); the `||` fallback covers
  non-git trees → `0.0.0-dev`.
- `-v` / `--version` accepted at the top-level dispatcher and in `serve`'s
  flag set (absorbs `cli-4`); prints the same block, exits 0.
- Tests: `run(["version"])` and `run(["-v"])` exit 0, first line
  `yolo 0.0.0-dev` (table-driven in `main_test.go`); no network.
- Docs: README build section → `just build`; the e2e reference in
  `CONTEXT.md` / `PROGRESS.md` becomes `just e2e-live` (script path unchanged).

## 3. Logging rework (slog-based)

**Core reimplementation of `internal/log`** — package name and `*log.Logger`
type stay, so cross-package wiring (`Deps.Log`, server deps, main) is
untouched:

- `Logger` wraps a `rotatingWriter` (the proven append + 5 MiB → `.1`
  single-generation rotation, refactored to an `io.Writer`) plus a
  `*slog.Logger` (text handler) on top.
- Explicit `Debug/Info/Warn/Error(msg string, args ...any)` methods; a nil
  `*Logger` is a no-op (the methods guard, so promoted-slog-on-nil panic is
  impossible) + `Close()`. `Infof`/`Errorf` are removed; the ~23 existing call
  sites convert mechanically to slog style.
- New `log.Noop()` (discard handler) — the engine uses it for a nil
  `Deps.Log`, closing `troubleshoot-2` (P1 panicking nil deref).
- **Level**: `YOLO_LOG_LEVEL` = DEBUG/INFO/WARN/ERROR, case-insensitive,
  default INFO, invalid → INFO (mirrors upstream `OPENCODE_LOG_LEVEL`).
  Static per process (read once at `New`).
- **stderr**: `YOLO_PRINT_LOGS=1` mirrors to stderr too (upstream
  `OPENCODE_PRINT_LOGS` parity). In TUI mode stderr is the TUI's terminal —
  opt-in, documented in README.
- **Line format** (slog text handler, UTC):
  `time=2026-08-22T10:00:00.000Z level=INFO run=3fa2c1b9 msg=serving on addr=127.0.0.1:4096`
  — `run` = 8-hex process id minted in `New` (upstream `run=` parity); a thin
  handler wrapper forces `r.Time` to UTC before delegating.
- **CWE-117 absorbed for free** (`security-5`): the text handler quotes/escapes
  non-alphanumeric values, so embedded newlines cannot forge log lines.
- File stays `<dataDir>/log/yolo.log`; open-failure no-op-with-retry behavior
  stays (best-effort logger). `Close` stays idempotent (a second call is a
  no-op) — the existing contract.
- **Keys are never logged.** Auth logs the resolution *source*
  (`source=env|auth.json|config`), config logs the path + error, never
  content (golang-security).
- **TUI-purity consequence:** non-test files under `internal/tui/` cannot
  import `internal/log` (root principle 4), so TUI-local lifecycle lines live
  in `cmd/yolo` (`tuiCmd` around `tea.Run`); the wire side is covered by
  server/engine logs. This is a design constraint, not a gap.

**New log points** (INFO unless noted; snake_case keys: `session_id model
tool exit_code latency_ms bytes status provider round source reason path`):

| Area | Points |
|---|---|
| cmd | `yolo starting` (mode/workdir/version), `serving on` **in TUI mode too** (the diagnosed gap), `received <sig>, shutting down`, TUI start/end |
| engine | turn start (session_id/agent/model), round start/end (+`latency_ms`/finish), tool start/end (+`exit_code`/truncated), abort (+reason), doom-loop trigger, overflow detection |
| LLM drivers | request start (provider/model), request end (+status/latency), errors (+decoded provider message) — local file only |
| tools | bash command (truncated ~200 chars) + exit; write/edit path; read path; grep/glob pattern + result count |
| storage | DB open + migrations applied |
| config | load (path, error if any) — never content |
| auth | resolution (provider, source) — never the key |
| permission | existing error paths kept; decisions at DEBUG |

**Tests:** level filtering; rotation (existing, moved); newline-escaping
(forged line → quoted); `YOLO_PRINT_LOGS` mirror; UTC format; `run=`
presence; no-op nil + `Noop()`; new call sites asserted through a
`log.NewTo(w io.Writer) *Logger` test constructor (captured buffer; no
rotation, no network).

## 4. Backlog fixes (12)

Each fix: one gate-green commit, 5-step TDD, finding ids from
`DEFERRED.md`. Absorptions list the duplicate findings closed by the same fix.

Permission cluster (`internal/permission/service.go`):
- **① P0 `SetDataDir` data race** (`concurrency-1 P0`) — read `s.dataDir`
  under the existing mutex in `decisionFor`. Test: 2 concurrent sessions,
  `-race`.
- **⑧ P1 cross-project rule bleed** (`design-1 P1`; absorbs `troubleshoot-4 P2`
  — same root, the per-turn `SetDataDir`/`SetConfigRules` calls on the shared
  service) — config rules become a parameter of the permission ask (the
  engine passes its turn's rules); per-turn `SetConfigRules` state is removed.
  Kills both instances of the finding (engine global + shared-Service state).
  Test: concurrent sessions with different project rules → no
  cross-contamination.
- **② P1 double-settle** (`concurrency-2 P1`) — one lock-held claim of the
  requestID: both `Reply` and ctx-cancel try to remove the pending entry; only
  the remover emits `permission.replied` + writes the row. Test: concurrent
  reply+cancel → exactly one event, one row flip.

Server cluster:
- **③ P1 `yolo.jsonc` lost updates** (`concurrency-2 P1`; absorbs `safety-1 P2`)
  — one mutex around read→merge→write for project + global config writes
  (writes are rare; no per-path map). Test: concurrent PATCHes, both merges
  survive.
- **⑨ P1 `authState` missing branch** (`design-1 P1`) — add the
  `options.apiKey` branch so the auth view matches runtime key resolution.
  Test: provider configured with only `options.apiKey` reports present.

LLM cluster (④ first, ⑦ consumes its output):
- **④ P1 error envelope dead path** (`concurrency-1 P1`; absorbs `safety-1 P1`)
  — on non-2xx, read the body (capped, 64 KiB) *before* closing and decode
  the provider error message (openai/anthropic `error.message`); surface it as
  the round error; `isOverflowError` runs against the decoded text (reviving
  the graceful-overflow path for provider 400s). Both drivers. Tests:
  in-process `httptest` 400/429 envelopes.
- **⑦ P1 `overflowRe` over-match** (`troubleshoot-1 P1`) — replace the
  over-broad `(?i)(context|tokens?|too long|exceeds)` with upstream's curated
  classifier (verified 2026-08-22 against
  `/tmp/opencode-upstream/packages/llm/src/provider-error.ts` +
  `packages/opencode/src/provider/error.ts`): the 28-entry `patterns` list
  (port byte-faithful), AND-NOT the 3 `exclusions` (throttling/service-
  unavailable prefix, rate limit, too many requests), OR a 400/413 status with
  no body, OR `error.code == "context_length_exceeded"` in the decoded body,
  OR status 413. 401/403/429 etc. then surface as real errors (turn ends
  errored, the model sees the decoded text). Engine-test pins update →
  deviation-log entry.

Storage/tool cluster:
- **⑤ P1 `Time.Start` loss** (`safety-2 P1`) — `PartToProtocol` restores
  `Time.Start` (the row already carries it via `ProtocolToPart`). Round-trip
  test.
- **⑥ P1 bash `timeout:0` / huge-n** (`safety-4 P1`; absorbs `security-2 P2`,
  `error-7 P3`, `troubleshoot-2 P3`) — reject `timeout <= 0` (upstream
  declares PositiveInt — parity; tool-result error naming the constraint) and
   clamp values above `2^31-1` ms (≈24.8 days) to that ceiling, so the
   `time.Duration` (int64 ns) conversion can never wrap. Tests: 0 → error
   result; huge-n → clamped, no overflow.
- **⑫ P1 unbounded glob walk** (`security-1 P1`) — port upstream's early stop
  (verified 2026-08-22: `packages/core/src/ripgrep.ts` takes `limit + 1` from
  the walk stream — collection stops as soon as the 101st match is seen;
  output = first 100 in walk order; a truncation note is appended when more
  than the limit were observed). yolo's walker stops collecting past the cap
  and returns the first 100 in walk order, with the same truncation note.
  Test: fixture tree > cap — bounded output, no full walk.

Engine hot-path perf (last):
- **⑩ P2 O(n²) part persist** (`performance-1 P2`) — deltas accumulate in
  memory + emit SSE as today; the full text is written to the DB once at part
  finalization (single upsert). Wire contract unchanged. Accepted trade,
  documented: a crash mid-turn loses the in-flight part text (the turn is not
  durable across crashes anyway). Benchmark: wave-13 baseline vs after.
- **⑪ P2 O(R²·M) `messagesFor`** (`performance-7 P2`) — per-turn in-memory
  history snapshot (load once at turn start, append assistant/tool rows per
  round); the LOCKED history→llm mapping is untouched (extracting it is
  0.3.0 `refactor-6`). Tests: engine e2e (fake driver) — identical requests
  across rounds; contract replays stay green.

**Pin/contract impact:** ④/⑥/⑦ change error text the model and tests see —
resolve per principle 5 (tests define the contract): update the pins, log
deviations. REST goldens and the SSE event set are untouched.

## 6. Constraints (unchanged from v1)

- **Zero telemetry** (root principle 1): all logging is local-file (opt-in
  stderr); nothing is ever sent to a remote server. OTEL/OTLP code and the
  telemetry-identity field stay absent; `OTEL_*` env vars stay inert.
- **No new deps**: `log/slog` is stdlib. The pinned dep set is untouched.
- **TUI import purity** (root principle 4): `internal/tui` non-test files
  still import only `internal/protocol` + `internal/tui/*`.
- **Verbatim pins** (root principle 3): `session/prompt/*.txt` +
  `tool/desc/*.txt` byte-identical; sha256 pins untouched.
- **Single wire deviation**: `x-yolo-directory` — unchanged.
- **Tests never hit the network**; LLM-driver tests use in-process
  `httptest`; engine e2e uses `YOLO_LLM=fake`.
- **Gate** per commit: `go vet ./... && go test ./...` + `gofmt -l .` clean +
  `golangci-lint run ./...` clean; `go test -race` on touched
  permission/storage/server packages during development.
- **Upstream reference**: `/tmp/opencode-upstream` (v1.18.18) for the ⑦ and ⑫
  parity checks.
