# Yolo v0.1.2 — Skill-Driven Code Review

- **Date:** 2026-08-19
- **Status:** Approved design (all sections confirmed by user)
- **Target branch:** `v0.1.2_skills_review` off `main` (v0.1.1 tip `1784ac0`)
- **Inputs:** the 15 hash-locked golang skills in `.agents/skills/` (pinned in `skills-lock.json`) and the as-built v0.1.1 codebase (~20,100 Go lines across `internal/{protocol,config,auth,bus,glob,log,llm,permission,protocol,provider,server,session,storage,tool,tui}` + `cmd/yolo`)
- **Constraint that shapes everything:** the executing agents have a **small context window**. All heavy reading is delegated to subagents; the orchestrator session only ever sees file lists, stats lines, and diff summaries. Spec and plan are written up front; execution happens in later sessions following the plan wave by wave.

## 1. Purpose & decisions

v0.1.2 reviews the released v0.1.1 codebase with **each of the 15 golang skills as a review lens**, one wave per skill, in severity order. Each wave: scoped review subagents → findings files → fix subagent (policy B) → full gate → checkpoint commit. The output is both a hardened codebase and a populated 0.2.0 backlog.

## 3. Wave protocol

Every wave k (1–15):

1. **Review** — dispatch the wave's review subagents (parallel, ≤3 at once; independent chunks, no shared state).
2. **Aggregate** — orchestrator reads each findings file's `Stats` line and finding IDs only (grep, never full bodies).
3. **Commit findings** — `docs(review): v0.1.2 — <skill>: N findings (P0:a P1:b P2:c P3:d)`.
4. **Fix** — one fix subagent for all fixable findings of that skill (§4). Skipped if zero fixable findings.
5. **Gate** — orchestrator runs `go vet ./... && go test ./...`, `gofmt -l .` (must print nothing), golangci-lint.
6. **Checkpoint** — `docs: checkpoint — v0.1.2 wave N (<skill>) done, next wave N+1 (<next skill>)` + roll `PROGRESS.md`.

User may stop after any wave; the branch is shippable at every green checkpoint.

## 4. Subagent protocol (review)

Fixed prompt skeleton per subagent (exact prompts live in the plan file):

1. Read `.agents/skills/<skill>/SKILL.md` fully — it is the lens, applied verbatim.
2. Read `docs/superpowers/reviews/v0.1.2/CONTEXT.md` (≤ ~80 lines, written in wave 0; contents below).
3. Scope = exact file list from the inventory (≤3k lines read-heavy / ≤6k grep-driven). **Grep-first, targeted reads.** No fixing. No long builds. `go test -run …` / `go vet` allowed for evidence only.
4. Write `docs/superpowers/reviews/v0.1.2/NN-<skill>-<chunk>.md`: **header first** (crash-safe), appendix per finding, must end with `COVERAGE: full|partial — skipped: <files>`. A subagent that cannot finish must write `partial` and return; orchestrator re-dispatches **one** split for the remainder, then accepts `partial`.
5. **Idempotent:** subagent checks for an existing findings file first — exists → resume/append; missing → create.

**Findings template:**

```markdown
# <skill> — <chunk>
Date: … · chunk: … · source files: NN
## Findings
- [<skill>-<n>] <P0–P3> <file:line> — <what + concrete impact> — fix: <suggestion> — contract-risk: none|pin|wire|render|behavior
## Deferred / Noted (no fix in 0.1.2)
- …
## Stats
P0:a P1:b P2:c P3:d
```

**Severity:** P0 crash/data-corruption/race · P1 correctness/security · P2 design/maintainability · P3 cosmetic.

**`contract-risk` is the auto-deferral mechanism:** `pin` (touches sha256-pinned text or goldens), `wire` (REST shape/SSE events/scoping), `render` (TUI output bytes), `behavior` (observable state machine change) → never fixed in v0.1.2, always deferred with a one-line reason.

## 5. Subagent protocol (fix)

One fix subagent per wave, running alone. Input: the wave's findings file paths + `CONTEXT.md` (paths only — it reads them itself).

Per finding, in file order:

1. **Re-verify against current code** (mandatory step 0 — kills false positives and drift from earlier waves).
2. Classify: `FIX` / `FALSE` (annotate with evidence) / `DEFERRED <reason>` / `WONTFIX <reason>`.
3. Bug fix → **failing test first** (TDD); mechanical change → existing suite stays green.
4. After each fix or ≤3-finding batch, the gate must be green (`go vet ./... && go test ./...`, `gofmt -l .`, golangci-lint) → one conventional commit (`fix(<scope>): …`).
5. Gate red after a fix → roll back that fix, mark `WONTFIX-<reason>`, continue.
6. If a "fix" requires touching pins/goldens/wire/render surfaces → stop that finding, mark `DEFERRED contract`, continue.
7. Annotate the findings file with final status per finding: `FIXED <sha>` / `FALSE` / `DEFERRED <reason>` / `WONTFIX <reason>`.

**False-positive guard:** if >50% of a skill's findings are rejected in the fix phase, orchestrator stops fix work and asks the user before continuing.

## 6. CONTEXT.md invariants (written in wave 0; every subagent reads it)

- Module `github.com/kido5217/yolo`, Go ≥ 1.25. Gate: `go vet ./... && go test ./...` + `gofmt -l .` (Go 1.26 formatter, must print nothing) + golangci-lint.
- **Zero telemetry** is a permanent principle; `OTEL_*` vars are inert; the config schema deliberately omits `experimental.openTelemetry`.
- **Single deliberate wire deviation:** header `x-yolo-directory` (upstream: `x-opencode-directory`). Faithful port otherwise.
- **Verbatim pins (sha256 in tests):** 14 session prompt files + all tool `desc/*.txt` — never modify. Golden fixtures only regenerate via the contract suite's `-update` flag, with approval.
- **TUI import rule:** non-test files under `internal/tui/` import only `internal/protocol` + `internal/tui/*` (+ stdlib/charm deps); `_test.go` may use `internal/server/testutil`.
- **Host toolchain quirk:** plain `import "embed"` + scalar `//go:embed` fails typecheck; the `import _ "embed"` workaround is intentional.
- **Tests never hit the network;** `YOLO_LLM=fake` + `YOLO_FAKE_SCRIPT` selects the scripted fake driver.
- **Faithful-behavior pins (do not "fix"):** SSE order = user message/parts *before* busy `session.status` (upstream-faithful, deviation 41); doom loop = sliding 3-identical window; `/quit` canonical with `/exit` alias; keymap pgup/pgdn + `\`+enter; JSONC comments not preserved on config PATCH rewrite.
- **Meta-rule:** flag the port's *internal* correctness and idiomaticity. Do not re-litigate upstream v1.18.18 design choices; do not propose re-deriving upstream behavior. Upstream clone for comparison (read-only): `/tmp/opencode-upstream`.

## 8. Orchestrator discipline (small context window)

The main session **never reads**: source files, findings bodies, subagent transcripts. It may read: `git log/status/diff --stat`, `wc -l`/file lists, findings-file `Stats` and ID lines only (grep), PR summaries. All heavy reading lives in subagents.

- **Parallelism:** ≤3 review subagents at once per wave; fix subagent always alone (it mutates code).
- **Failure modes:** `partial` coverage → one split re-dispatch, then accept + note; subagent crash → re-dispatch same prompt (idempotent findings file); fix batch stalls → mark remaining findings `DEFERRED stall`, continue wave; false-positive flood → §5 guard.
- **Stop rule:** after any wave. State recorded in PROGRESS.md; branch shippable at any green checkpoint.

## 9. Done means

- 15 waves complete (or user stopped early — recorded), every findings file at terminal status (every finding `FIXED`/`FALSE`/`DEFERRED`/`WONTFIX`).
- `DEFERRED.md` rolled up and committed.
- Final gate by orchestrator on PR head: `go vet ./... && go test ./...` + `gofmt -l .` + golangci-lint clean.
- PR opened with summary table; user reviews; merge user-decided; `v0.1.2` tag only on explicit go-ahead.
- PROGRESS.md active-task reset to "awaiting direction — 0.2.0+ has a populated defer list" (`DEFERRED.md` + wave-8 refactor backlog).

## 10. Risks

| Risk | Mitigation |
|---|---|
| Subagent context exhaustion mid-chunk | `COVERAGE: partial` contract + one split re-dispatch; chunk size caps in §2 |
| False-positive flood burns fix budget | mandatory re-verify step 0; >50% rejection guard; `FALSE` annotations kept as record |
| Fix breaks a faithful pin / golden | `contract-risk` auto-deferral; pins/goldens are read-only to fix subagents; gate (sha256 + golden tests) catches any slip |
| 33 review sessions take many hours | waves are stoppable; user can run in multiple sessions — each session resumption starts from the plan + PROGRESS.md |
| Orchestrator drifts into reading code | §8 rule written in the plan's per-session instructions; findings accessed via grep only |
| Upstream-faithful code "flagged" as bugs | CONTEXT.md meta-rule (§6); subagents instructed to compare against `/tmp/opencode-upstream` before flagging behavior diffs (read-only) |
