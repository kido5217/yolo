- [error-1] P1 internal/server/handlers_session.go:273 — handleSend passes `func(error){}` as the `onDone` callback to `Engine.Send`, discarding the turn's final error; the engine (internal/session/engine.go:315-381) sets `turnErr` for model-level failures (buildRequest error, LLM round error, max-rounds) without logging or publishing any event (only aborts are logged at engine.go:367), and the ported SSE set has no `session.error` type. Concrete impact: a failed model turn is invisible everywhere — no yolo.log entry, no SSE frame, TUI just shows the session going idle; violates "errors must be logged or returned, never vanished". Upstream `promptAsync` logs at this boundary (Effect.logError("prompt_async failed")). — fix: in handleSend, use an onDone that logs non-nil errors: `func(err error) { if err != nil { s.Log.Errorf("turn failed (session=%s): %v", id, err) } }` (nil *log.Logger is a no-op, safe); leave the TUI-visible half (missing session.error event) to the engine/event-set question in Deferred — contract-risk: none — STATUS: FIXED 2e2f8f6 (pin test TestSendLogsFailedTurn)
- [error-2] P2 internal/server/handlers_misc.go:117,129,134,158,178,183,213,234,239,250,253,273,285,325,336,389; internal/server/handlers_session.go:67,84,135,148,183,200,205,233,240,247,307,345 — ~28 handler 500 paths convert the underlying error into a generic envelope message (`"load config"`, `"lookup session"`, `"save auth"`, …) and discard the error without logging it. - [error-3] P2 internal/tool/grep.go:148-151 — `os.Stat(requested)` failure (most commonly: nonexistent search path) is swallowed and the tool returns the empty "No files found" output. The grepWalk comment (grep.go:238-240) says root-level errors are "load-bearing" and surfaced when nothing matched, but a missing root makes WalkDir's single erroring callback return nil (grep.go:197-199), so werr is nil and nothing surfaces. Concrete impact: the model believes a search ran and found nothing when the directory does not exist — misleading agent behavior, and inconsistent with the glob tool which errors ("glob path must be a directory"). Upstream errors here (ripgrep fails on a missing cwd; packages/opencode/src/tool/grep.ts). — fix: on stat error return `fmt.Errorf("grep path %s: %w", requested, serr)` (and, if the root is a file, keep resolving to its dirname) — contract-risk: behavior — STATUS: DEFERRED contract (behavior — a grep stat error on a nonexistent root changes the tool's output)
- [error-4] P2 internal/server/server.go:116-123 — initAuth treats every `auth.LoadFrom` error as "file missing = empty store". A corrupt or unreadable auth.json (JSON parse failure, I/O error) is silently swallowed; the boot-lifetime store then starts empty, and the first `PUT /auth/{id}` rewrites auth.json with a single entry, destroying the pre-existing file contents (which may still be manually recoverable) without ever warning the user. Contrast: the CLI path `yolo auth list` does surface load errors (cmd/yolo/main.go:333-337). — fix: `if st, err := auth.LoadFrom(s.authPath); err == nil { ... } else if !os.IsNotExist(err) { log the error (or fail boot) }` — contract-risk: none — STATUS: FIXED cbe91b8
- [error-5] P3 cmd/yolo/main.go:255-258 — the tea.Run() runtime error is mapped by tuiExit only to an exit code; a non-killed Run failure (e.g. terminal I/O error, "no tty") exits 1 with no message on stderr and no log line. TestTuiExitMapping pins only the exit code, so adding output stays test-compatible. — fix: in tuiMode, when runErr != nil and not tea.ErrProgramKilled, print `yolo: <err>` to stderr (and/or deps.Log.Errorf) before returning tuiExit(runErr) — contract-risk: behavior — STATUS: DEFERRED contract (behavior — visible stderr on a tea.Run failure)
