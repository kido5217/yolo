- [safety-1] P1 internal/glob/glob.go:155-158 — `mustCompile` discards `regexp.Compile` errors and returns a nil `*regexp.Regexp`; `segmentRe` emits a valid-looking but uncompilable empty class `[]` for segments like `[]`, `[]]`, `a[]b` (glob.go:132-146), so `segmentMatch` (:101) / `bare` (:107) nil-deref. Repro confirmed: `glob.Match("[]", x)`, `"[]]"`, `"a[]b"`, `"**/[]"`, `"[]x"` all panic. Pattern input is model/user-controllable: `glob` tool pattern (internal/tool/glob.go:136, evaluated per entry during `fs.WalkDir`), `grep` include pattern (internal/tool/grep.go:210), and every permission rule pattern on every tool call (internal/permission/permission.go:70, service.go:352). No `recover()` anywhere in internal/session or internal/tool, so one malformed pattern from the model (or a user permission config) crashes the entire single-process binary (server + TUI). — fix: on compile error return a literal segment (`regexp.QuoteMeta`), consistent with the existing unclosed-`[` literalization at glob.go:136-137, or propagate the error to `Match` callers; add a regression test asserting `Match` does not panic on `[]`, `[]]`, `a[]b`, `**/[]` — contract-risk: none
  - status: FIXED 0975325
- [safety-2] P1 internal/storage/dao.go:350 (tool branch :334-339) — `PartToProtocol` never restores `Time.Start`: `ProtocolToPart` stores it as the row's `time_created` (dao.go:304), but the default branch rebuilds `p.Time = PartTime{End: st.End}` (Start stays 0) and the tool branch leaves `p.Time` unset entirely (top-level `"time":{"start":0,"end":0}`; only `state.time` survives). Neither caller compensates: `internal/server/handlers_session.go:243-247` appends the result as-is, and engine replay (internal/session/engine.go:453-457) doesn't use start. After a restart, `GET /session/{id}/message` returns every persisted part with `start:0`, while upstream persists parts as whole JSON blobs (`/tmp/opencode-upstream/packages/core/src/session/sql.ts` PartTable `data json V1PartData`) and set `time:{start:Date.now()}` at creation (processor.ts:288/346/493/566/590), so upstream reload keeps real starts — the "inverse of ProtocolToPart" doc promise is broken. Round-trip test (storage_test.go:99-101) asserts only `Time.End`, so the loss is test-invisible. — fix: default branch `p.Time = PartTime{Start: r.TimeCreated, End: st.End}`; tool branch `p.Time = PartTime{Start: r.TimeCreated, End: st.Time.End}`; extend the round-trip test to assert `Time.Start` — contract-risk: behavior (auto-defer)
- [safety-3] P2 internal/storage/dao.go:308 — `ProtocolToPart` swallows the tool-state marshal error (`b, _ := json.Marshal(p.State)`); a `ToolState` whose `Input`/`Metadata` carries a NaN/Inf float makes `json.Marshal` fail, so `StateJSON=""` is persisted, and every later read (`PartToProtocol` dao.go:336/:346) fails with "unexpected end of JSON input" → `handleMessages` 500s on the entire message ("decode part") and engine history replay errors → the session is permanently unreadable after one bad write. (The map branch at :318 only marshals string/int64/*bool and cannot fail.) — fix: surface the marshal error from the persistence path (change `ProtocolToPart` to return an error or validate at `UpsertPart`); never write an undecodable blob — contract-risk: behavior (auto-defer)
- [safety-4] P2 internal/storage/dao.go:274 — `listPartsBy` orders parts by `time_created ASC` alone (milliseconds); parts created in the same millisecond are typical (multiple tool parts in one assistant turn), so their loaded order is undefined and can differ from original turn order on reload (TUI render order + engine replay order). `ListMessages` (dao.go:200) and `ListSessions` (dao.go:91) carry the same shape. — fix: add a deterministic secondary key (`ORDER BY time_created ASC, id ASC`) or a per-message monotonic sequence column — contract-risk: behavior (auto-defer)
