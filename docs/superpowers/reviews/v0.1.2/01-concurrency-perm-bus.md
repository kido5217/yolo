## Findings
- [concurrency-1] P0 internal/permission/service.go:96 — data race: `decisionFor` reads `s.dataDir` without a lock while `SetDataDir` (service.go:70-74) writes it under `s.mu`; the write runs in `runTurn` for every session (internal/session/engine.go:335) on the shared Service/Engine (cmd/yolo/main.go:129,164), and the read is the live path since no caller ever sets the `Meta["data_dir"]` override (service.go:97 is dead) — reachable with 2+ concurrent sessions; memory-model violation, -race-detectable (current tests never interleave), torn string-header read could in principle pick a wrong plan-matrix — fix: take `dataDir` under the same `s.mu` lock as `cfgRules` (extend the lock block at service.go:104-106) — contract-risk: behavior
- [concurrency-2] P1 internal/permission/service.go:179-181, 266-289 — double-resolve race: when a `Reply` and ctx-cancel land in the same `Ask` select, the ctx.Done branch calls `resolve` unconditionally and `resolve` still writes `db.ReplyPermission` + publishes `permission.replied` when `ok=false` (request already settled), so one requestID gets two `permission.replied` events (e.g. "once" then "reject") and the storage row flips against the user's actual reply; upstream cannot double-settle (Deferred settles once; its abort path publishes nothing — /tmp/opencode-upstream permission/index.ts:105-114) — fix: make `resolve` skip the DB write and event publish when the entry was not taken (`ok=false`), i.e. side effects conditional on the atomic map take — contract-risk: wire
- [concurrency-3] P2 internal/permission/service.go:276-278 — liveness: on a real `db.ReplyPermission` error (SQLITE_BUSY etc., not ErrNotFound) `resolve` returns without delivering, the entry is already removed from `pending` (so `Reply` now returns ErrNoPending), and the parked `Ask` blocks until ctx.Done — a transient SQLite error wedges the engine turn until abort; port-specific, upstream v1.18.18 permission service has no DB interaction (in-memory InstanceState) — fix: deliver the decision regardless of the DB error (log it), preserving the "reply always unblocks the waiter" invariant — contract-risk: behavior
- [concurrency-4] P3 internal/permission/service_test.go:76 — test flake risk: park-wait via `time.Sleep(100ms)` (also line 106, 131) instead of a deterministic signal can flip these -race tests under CI load — fix: poll `Pending` in a deadline loop (or signal parking via a helper) instead of sleeping — contract-risk: none
- [concurrency-5] P3 internal/bus/bus.go:14, 64 — redundant `closed` flag: both close sites (cancel at bus.go:43-51, overflow at bus.go:62-67) already run under the same `b.mu` guarded by map membership, so `!s.closed` in `Publish` is always true — dead check invites confusion in a concurrency surface — fix: drop the flag and rely on map membership (or keep one and document why) — contract-risk: none
