- [concurrency-1] P0 internal/server/handlers_misc.go:73-77 — `authSnapshot()` returns `s.authStore` (type `auth.Store` = `map[string]Entry`, internal/auth/auth.go:23) under `authMu`, copying only the map header: all callers then do lock-free map reads (`store[id]` at handlers_misc.go:88 via GET /provider and GET /provider/auth), while `handleAuthPut`/`handleAuthDelete` (handlers_misc.go:257-260, 269-272) write the same underlying map in place under the lock (`Store.Set`/`Delete` use value receivers and mutate the shared map; the field is never reassigned) — concurrent `PUT /auth/{id}` + `GET /provider` is a race that the runtime escalates to `fatal error: concurrent map read and map write` (hard process crash; existing tests pass only because no test interleaves auth writes with provider reads) — fix: deep-copy entries in `authSnapshot()` (`out := make(auth.Store, len(s.authStore)); for k, v := range s.authStore { out[k] = v }`) — contract-risk: none
- [concurrency-2] P1 internal/server/handlers_misc.go:180-197 — `writeProjectLayer` (and `handleGlobalConfigPatch` at 211-246) does unserialized read-modify-write of `yolo.jsonc` (ReadFile → merge → WriteFile) with no mutex or conflict check: two concurrent `PATCH /config` (or PATCH /config + PATCH /global/config on the same file) race; last write wins and the other request's merge is silently lost (config corruption-by-loss) — fix: guard the RMW with a per-path `sync.Mutex` (or optimistic retry comparing expected file content) — contract-risk: wire
- [concurrency-3] P2 internal/server/handlers_misc.go:257-260,269-272 — `authMu` is held across disk I/O (`auth.SaveTo` = MkdirAll + Marshal + WriteFile, internal/auth/auth.go:55-64): every `authSnapshot()` reader (GET /provider, GET /provider/auth — frequent TUI polls) is serialized behind auth-file writes, so a slow or failing disk stalls the provider endpoints; skill: "Mutex held across I/O — keep critical sections short" — fix: mutate and deep-snapshot the store under the lock, call `auth.SaveTo` after `Unlock` — contract-risk: none
- [concurrency-4] P2 internal/server/testutil/testutil.go:156-181 — `ParkAsk` spawns a fire-and-forget goroutine (`go func() { _, _ = ts.PermSvc.Ask(...) }`) with no exit path (no context/done): it stays blocked until the ask is replied to, so any test that parks an ask and never replies leaves a leaked goroutine; additionally the 2s visibility deadline silently returns without `t.Fatalf`, so a park that never becomes visible surfaces later as a confusing `len(pend) != 1` failure instead of a clear timeout — fix: pass a context cancelled via t.Cleanup (or retain the goroutine's ask so cleanup can settle it) and `t.Fatalf` on deadline — contract-risk: none
- [concurrency-5] P3 internal/server/server.go:51,155-158 — `Server.mu` guards only the `Addr()` read, but `Start` writes `s.addr`/`s.srv` without the lock (server.go:146-147): inconsistent locking that would be a real race if lifecycle calls crossed goroutines, and `Addr()` is unused (cmd/yolo uses Start's return value), so the mutex is dead weight giving false assurance — fix: guard the Start writes with the same lock or drop `mu`/`Addr()` — contract-risk: none
- [concurrency-6] P3 internal/server/contract_test.go:420-425 — `newSrvFakeEnv` mutates package-global env via `os.Setenv`/`os.Unsetenv` (t.Cleanup reset): unsafe under `t.Parallel()` — concurrent env reads/writes in the same package race, and `os.Setenv` is a known parallelism hazard; no current test parallelizes, so latent — fix: use `t.Setenv` (auto-cleanup + refuses parallel tests by design) — contract-risk: none
