# golang-safety — tui
Date: 2026-08-20 · chunk: tui · source files: 28
## Findings
- [safety-1] P2 internal/tui/client/client.go:45 - backoff computes `time.Second << uint(n)`; per the Go spec a shift count >= 64 yields 0, so from the 64th SSE reconnect attempt the backoff is 0 and `Events` (client/event.go:33) tight-loops reconnect attempts (each failing fast) for as long as the server stays down. Reaching n=64 needs ~30 min of continuous outage (2+4+8+16+30s x 59) - laptop sleep or a long server crash, field-plausible. Internal Go TUI client; no upstream equivalent (v1.18.18 is TS-only). - fix: clamp the shift, e.g. `d := time.Second << uint(min(n, 5))` (2^5 s already hits the 30 s cap) - contract-risk: none
- [safety-2] P2 internal/tui/client/event.go:58 - SSE line scanner max token is 1 MiB; a single `data:` line larger than 1 MiB (e.g. `message.part.updated` carrying a tool output from reading a file of ~700 KB+ after JSON escaping) makes `Scan()` fail with `bufio.ErrTooLong`, the stream errors and reconnects, and that event is silently dropped - the transcript stays incomplete (no re-hydration until the user re-enters the session). - fix: raise the token cap (e.g. 16 MiB); a line is one event, so no per-line skip logic is needed - contract-risk: behavior (oversized events currently lost would then render; auto-defer)
- [safety-3] P3 internal/tui/prompt.go:48 - `strings.HasPrefix(c.Name[1:], prefix)` panics if a command `Name` is empty or lacks the `/` prefix. Unreachable today (in-process server catalog is pinned, all five names start with `/`, internal/server/handlers_misc.go:27-31), but the TUI trusts wire input - a future catalog entry or a different server would crash the whole UI. - fix: skip malformed entries, e.g. `if len(c.Name) < 2 { continue }` - contract-risk: none
- [safety-4] P3 internal/tui/app.go:223,240,290 - `hydrateCmd` (ListSessions/ListMessages/ListCommands/GetSession/GetConfig) and the slash-`/new` no-session path (CreateSession at :290) run on `context.Background()` with no deadline, while every other TUI command uses a 5 s `WithTimeout` (:439,:491,:627,:672,:679,:724). A hanging server leaves home/session hydration stuck forever with no error surfaced (stale list, no toast) instead of degrading after 5 s. - fix: wrap in the same 5 s `WithTimeout` - contract-risk: none
