## Findings
- [datastruct-1] P2 internal/tool/write.go:119 — `diffCounts`/`lcsLen` is a full O(len(old)×len(new)) LCS DP over lines (the code comment itself documents O(len(a)*len(b)) time); it runs on EVERY write (write.go:108) and edit (edit.go:155) where the file existed before — the only purpose is two small ints for part meta. Concrete impact: a 5,000×5,000-line rewrite is 25M inner steps each doing a string compare (worst case full-line compares); a 10k×10k rewrite is ~1 second+ of pure stall inside a model turn, per invocation. Fix: use a cheaper line-diff-count — hash lines first (map lookup instead of string compare per cell), or banded Myers around the diagonal (O(n·d)) with a fallback to a coarse count when n·m exceeds a size threshold; ANY alternative must reproduce the exact counts the pinned tests assert (write_test.go / edit_test.go check meta values). — contract-risk: none
- [datastruct-2] P3 internal/tool/shell.go:105 — `regexp.MustCompile(fmt.Sprintf(...))` compiles a fresh marker regex on every `Exec` (per-call allocation + compile on the bash hot path; the pattern only varies by the per-process counter n). Fix: compile one shared `^__YOLO_END_(\d+)_([^\s]*)$` at spawn and compare the captured counter to the expected n (strconv on m[1]); marker-protocol semantics unchanged. — contract-risk: none
- [datastruct-3] P3 internal/tool/grep.go:227 — `strings.Split(string(b), "\n")` materializes a whole-file string copy plus a per-line slice for EVERY file walked (files up to 10MB per grepMaxSize) before any line is matched; a 10MB file with 300k lines allocates ~5MB of slice headers transiently per file even when 0 lines match. Fix: scan with `strings.IndexByte`/read-line loop (or bytes splitting per line) so only the matched line substrings are retained; the 100-match cap (plan-pinned) is already enforced. — contract-risk: none
- [datastruct-4] P3 internal/session/policy.go:81 — `toolSchemaList` (called from `buildRequest` on EVERY round, up to 50/turn) calls `t.Schema()` which builds a fresh nested map tree per tool per call, then `json.Marshal` of it — re-materializing + re-encoding 7 static schemas per round. Fix: hoist the static schemas once (e.g. precompute `json.RawMessage` per tool at engine construction; encoding is deterministic so wire bytes are identical). — contract-risk: none
