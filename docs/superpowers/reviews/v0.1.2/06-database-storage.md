## Findings
- [database-1] P1 storage/db.go:33-42 — `PRAGMA busy_timeout` and `PRAGMA foreign_keys` are **per-connection** SQLite settings, but `Open` runs them once via `d.Exec`, which only applies them to the single pool connection checked out at that moment. `sql.DB` pools conns: open conns are unbounded here (no `SetMaxOpenConns`), and the default `MaxIdleConns=2` means the 3rd+ idle conn is closed and **fresh bare conns** are opened on demand. Every such conn runs `foreign_keys=OFF` (SQLite default), so `ON DELETE CASCADE` silently stops applying: `DeleteSession`/`DeleteMessage` on a bare conn leave orphaned message/part/todo rows (the `TestCascadeDelete` test only passes because its single pooled conn is reused; orphaned rows would then reappear via `ListMessages` on a deleted session). Same class: `busy_timeout=0` on bare conns → immediate `SQLITE_BUSY` under concurrent writes (engine turn writes vs server-side permission reply) instead of waiting up to 5 s. `journal_mode=WAL` is the exception — it is persistent in the DB file, so that one line is fine. — fix: set all three per-connection via the DSN; the pinned driver modernc.org/sqlite v1.56.0 supports mattn-style keys applied on every connection open (verified in driver source, driver.go:72-98, sqlite.go:365-418): `sql.Open("sqlite", "file:"+path+"?_foreign_keys=1&_busy_timeout=5000&_journal_mode=WAL")`, then delete the Exec-PRAGMA loop — contract-risk: none (restores the behavior the spec-pinned DDL already declares: `REFERENCES ... ON DELETE CASCADE` in migrate.go:30,40,60 and the busy-wait the comment at db.go:26 promises)
- [database-2] P2 storage/db.go:28-48 — no connection pool configuration at all (no `SetMaxOpenConns`/`SetMaxIdleConns`/`SetConnMaxLifetime`/`SetConnMaxIdleTime`) — skill rule 11 ("connection pool MUST be configured"). Unbounded open conns on a single-writer SQLite amplify `database is locked` contention (each extra conn is a potential second writer) and are the mechanism that makes database-1 reachable (idle reaping → bare replacements). — fix: for a single-process SQLite store the safe idiom is one shared, properly-PRAGMAd conn: `raw.SetMaxOpenConns(1); raw.SetMaxIdleConns(1)` after `sql.Open` — with the database-1 DSN fix this is belt-and-braces; either one alone mitigates, both together are correct. Query latencies here are sub-10 ms so serializing on one conn is a non-issue — contract-risk: none
- [database-3] P2 storage/dao.go:68 (systemic: every DAO method in dao.go, db.go:56,78, migrate.go:88) — zero context propagation: the package has no `ctx` parameters and no `*Context` variants anywhere (repo-wide grep: no `QueryContext`/`ExecContext`/`QueryRowContext`/`BeginTx` in any .go file) — skill rule 3 ("Context MUST be passed to all database operations"). Impact: a cancelled client request cannot cancel the in-flight DB op; a write blocked on the SQLite write lock stalls the full busy_timeout (5 s) even after its context is done; no deadlines can be attached. — fix: thread `context.Context` through the DAO API (e.g. `CreateSession(ctx, r)` etc.) and switch to the `*Context` methods — ripples into `internal/permission`, `internal/session`, `internal/server` call sites; recommend a deliberate 0.2.x API change rather than a mid-wave signature churn — contract-risk: none
