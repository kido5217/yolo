# golang-safety — session+llm+provider
Date: 2026-08-20 · chunk: session+llm+provider · source files: 20
## Findings
- [safety-1] P1 internal/llm/openai.go:31-34 — read-after-close on the response body: `resp.Body.Close()` runs BEFORE `oaUpstreamError(resp)` (openai.go:42-43: `io.ReadAll(io.LimitReader(resp.Body, 4096))`), and an h1/h2 body read after Close always returns 0 bytes + error (`http: read on closed response body` / GOROOT 1.26.6 `net/http/transport.go:3068-3070`, `h2_bundle.go:9899-9903`; verified empirically with an httptest 400 server: post-close read len=0, pre-close control read len=89). Consequence: the "body ≤ 4KB drained" contract in openai.go:40 is never met — every non-2xx (bad key, insufficient balance, model-not-found, provider 400s) degrades to the generic `upstream error (HTTP N): N Status` text, and `isOverflowError` (`engine.go:835` `(?i)(context|tokens?|too long|exceeds)`) can never match a real provider 400 such as "prompt is too long" / "maximum context length exceeded", so the graceful overflow path at engine.go:600 (pre-stream) and engine.go:712 (mid-stream) is dead code for API 400s and the turn hard-fails instead of saving the synthetic overflow note (engine.go:557 doc promises it). Port-introduced: upstream v1.18.18 uses the AI SDK `streamText` (packages/opencode/src/session/llm.ts:280); the hand-rolled Close-then-Read exists only here. Masked by tests: `TestOpenAIUpstream429IsTransient` (llm_test.go:145) is the only non-2xx test and asserts only `IsTransient(err)`, never the message. — fix: delete the early `resp.Body.Close()` at openai.go:32 and anthropic.go:38 and close via `defer resp.Body.Close()` inside `oaUpstreamError` (read first), or drain before closing; add an assertion on the error text (e.g. contains "slow down") to the 429 test and a 400 overflow-text test. — contract-risk: behavior (observable error strings change; API-400 overflow graceful path becomes reachable)
- [safety-2] P3 internal/provider/zen.go:147 — the `http.Client` injected into `New` (provider.go:92, stored provider.go:100) is used only for LLM drivers (`DriverFor` provider.go:277-282); the zen catalog fetch (`CatalogPolicy.fetch`) unconditionally uses `http.DefaultClient`, and `FetchKido` builds its own client (kido.go:26). A caller-supplied client (custom timeout, TLS, proxy) is silently bypassed for catalog fetches. — fix: thread `r.client` through `NewCatalogPolicy` (add a `client` field, pass it at provider.go:113) and into `FetchKido`, defaulting to `http.DefaultClient` when nil. — contract-risk: none
- [safety-3] P3 internal/provider/kido.go:55-61 — no per-entry validation of the live `/v1/models` response: an entry with an empty `id` enters the catalog under an empty Model ID (breaking `Resolve`/catalog lookups), and `NCtx <= 0` yields `Context: 0` and `Output: min(32768, NCtx/8)` = negative, which unlike the config-provider path (zero `max_tokens` is omitted / defaulted, provider.go:174, anthropic.go:64-67) would be sent on the wire as a negative `max_tokens`. The fallback (kido.go:12-17) fires only on whole-response failure/empty `data`, not on malformed entries. — fix: skip entries with `d.ID == ""` or `d.Meta.NCtx <= 0`; if all are skipped, return `kidoFallback`. — contract-risk: none
