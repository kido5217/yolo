# golang-design-patterns — core+session+permission
Date: 2026-08-21 · chunk: core+session+permission · source files: 24

## Findings
- [design-1] P1 internal/session/engine.go:350 + internal/permission/service.go:54,73,104 — Shared `Service.cfgRules` global: the engine calls `SetConfigRules` per turn from the *session's* project-dir config, but `decisionFor` (re-run by `Ask` for every `DecisionPre == AskAction`, i.e. every real ask) reads whatever the most recent turn set. With concurrent sessions in different project dirs, another session's config permission rules contaminate the ask re-evaluation (an ask can be auto-allowed or denied by the wrong session's rules). Port-specific: upstream v1.18.18 `permission.ask` receives the ruleset per request in its input; the duplicated ruleset assembly (engine `rulesetForRow` vs service `decisionFor`, with different wildcard gating via `corePermissions`) is the same root cause. — fix: thread the turn's ruleset (or cfg rules) through `permission.Request` into `Ask`/`decisionFor`; delete the global, the per-turn `SetConfigRules`, and the duplicated merge (align with upstream's per-request ruleset). — contract-risk: behavior
- [design-2] P2 internal/permission/service.go:58,65-85 — State configured via post-construction setters (`New(db, b)` + `SetLogger` + `SetDataDir` + `SetConfigRules`): "set-once-before-use" is documented but unenforced, and the engine re-sets `DataDir` on every turn (engine.go:338) even though it is process-constant; a caller skipping a setter gets silent zero-value config. — fix: move `Logger`/`DataDir` (process-constant) into `New` (options or args), deleting the setters and the per-turn call; `SetConfigRules` goes away with design-1. — contract-risk: none — status: FIXED 39a196e (ctor takes log+dataDir; SetLogger/SetDataDir and the per-turn set removed; SetConfigRules kept until design-1 lands in 0.2.0)
- [design-3] P2 internal/session/engine.go:216,1073,1086 — `Engine.Shutdown` drain is incomplete: `generateTitle` goroutines (30s timeout, parented to `context.Background()`, untracked) are neither cancelled nor awaited, so "drains the engine for process exit" is broken for engine-owned work — the title goroutine can still write the DB and publish `session.updated` after Shutdown returns and the store closes. — fix: track title cancels (separate set or under the busy machinery), cancel in `Shutdown` (optionally bounded-wait like the busy turns). — contract-risk: behavior
- [design-4] P2 internal/session/engine.go:85 — `New(d Deps)` returns `*Engine` with no error and no validation: required deps (DB, Bus, Prov, Perm, Tools) are nil-accepted; a miswired dep panics deep in the un-recovered `runTurn` goroutine, crashing the whole single binary. Skill: catch bad config at construction, not at runtime. — fix: validate required Deps fields and return `(*Engine, error)` (or an explicit `MustNew` with a comment). — contract-risk: none — status: FIXED b15a220 (New validates DB/Bus/Prov/Perm/Tools and returns (*Engine, error); TestNewValidatesRequiredDeps covers all five + valid construct)
- [design-5] P2 internal/permission/service.go:199,281 — `Reply` is check-then-act across two lock acquisitions: the pending lookup (:205-207) and `resolve`'s delete (:282-289) are not atomic, and `resolve` publishes `permission.replied` regardless of whether the entry existed. Two concurrent replies to one request ID (the wire allows duplicate POSTs) both pass the check and the loser still emits an orphan `permission.replied` event (empty sessionID) plus a DB write. — fix: re-check under the lock in `resolve` and skip persist+publish when the entry is absent (atomic claim). — contract-risk: behavior
- [design-6] P3 internal/session/prompt.go:162 — `buildSystemPromptForTest` is a test-only constructor in the production API (named `*ForTest`, stale "future engine" comment); the engine's own instruction appending (engine.go:428-438) duplicates `buildCore`'s instruction handling, so the prompt-builder seam is split in two places. — fix: move the test seam to a `_test.go` file or fold instructions into `BuildSystemPrompt` so the engine path uses the single core. — contract-risk: none — status: FIXED b15a220 (seam moved verbatim to prompt_test.go over buildCore; engine path unchanged, engine.go:428-438 appending untouched)
- [design-7] P3 internal/session/prompt.go:124 — `gitCache` is an unbounded, non-expiring package-global map (implicit global state; a dir that becomes a git repo mid-process stays "no" forever, and the env-block text is baked into every round's system prompt). — fix: bound the cache (small LRU) or re-detect on a TTL. — contract-risk: behavior
- [design-8] P3 internal/permission/service.go:105 — Dead per-request seam: `decisionFor` honors `req.Meta["data_dir"]`, but the engine never sets `Request.Meta` and `DecisionFor` has no production callers outside tests — the override is unreachable in the real flow while the global `s.dataDir` (design-2) is what actually gets used. — fix: delete the override, or pass dataDir through the request as part of the design-1 redesign. — contract-risk: none — status: FIXED 39a196e (dead Meta["data_dir"] override deleted; decisionFor uses only the ctor dataDir)
