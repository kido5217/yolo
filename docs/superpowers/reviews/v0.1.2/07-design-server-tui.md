# golang-design-patterns — server+tui-core
Date: 2026-08-21 · chunk: server+tui-core · source files: 13

## Findings
- [design-1] P1 internal/server/handlers_misc.go:96-112 — `authState` is a second, incomplete implementation of the spec-order key resolution: it mirrors `auth.ResolveKey` (auth.go:120) except the `cfg.Provider[id].Options["apiKey"]` branch, so a provider configured with ONLY `options.apiKey` gets wire status `"missing"` on GET /provider and /provider/auth (and the TUI model-dialog dot) while the runtime (engine.go:284, provider.go:169 via ResolveKey) actually finds and uses the key. Two parallel implementations of one resolution order are the root cause and have already drifted. — fix: make the status a projection of the single resolver — add `auth.ResolveStatus(providerID, store, cfg, env) (status, source)` covering env -> store -> config APIKey -> config Options["apiKey"], and have `authState` delegate to it — contract-risk: wire (status field value; existing goldens unaffected — the /provider golden config has no options.apiKey provider)
- [design-2] P2 internal/server/server.go:64-67,77-81 — `NewServer` wraps a second, separately constructed `*Server`: `build(d)` creates its own `&Server{Deps: d}`, runs `initAuth()` on it, and binds every handler to THAT instance, leaving the outer Server's `authMu`/`authPath`/`authStore`/`authErr` fields zero-valued and never written (dead state), while the struct doc claims "Server holds Deps plus the optional in-process listener." A future handler author who adds a method on the outer instance (or reads `s.authStore` there) silently operates on an empty store. — fix: construct one instance — make `build` a method `(s *Server) build() http.Handler` that populates `s` (initAuth + mux), `NewServer(d)` returns that instance, and `New(d) http.Handler` becomes `NewServer(d).Handler()` — contract-risk: none — status: FIXED 6cbff51 (build is now a method on the single instance; New(d) = NewServer(d).Handler(); doc claim now true)
- [design-3] P2 internal/server/server.go:163 — `Start` builds `&http.Server{Handler: s.handler}` with no `ReadHeaderTimeout`; `yolo serve --addr` accepts arbitrary addresses (main.go default 127.0.0.1:4096, user-overridable to 0.0.0.0), where slow/broken header sends hold connections unbounded (skill: limit everything / timeout every external call). Read/Write/Idle timeouts must stay off for the long-lived SSE endpoint, but a header-read timeout is safe for it. — fix: set `ReadHeaderTimeout` (e.g. 10s) on the `http.Server` in `Start` — contract-risk: none (well-behaved clients unaffected) — status: FIXED 6cbff51 (ReadHeaderTimeout 10s; Read/Write/Idle stay off for SSE)
- [design-4] P2 internal/server/handlers_misc.go:129-131 — `handleProviderAuth` hardcodes `dir := s.WorkDir` while its sibling `GET /provider` is request-scoped via `s.scoped(w, r)` (the plan comment at :35-36 scopes /provider explicitly; no such rationale exists for /auth), so the two endpoints of one resource family report config-defined providers/auth status against different directories whenever `x-yolo-directory` != server work dir; upstream resolves instance route dirs from the request (workspace-routing: directory query → header → cwd). It also loads config twice (inside `providerEntries` and again at :141). — fix: scope with `s.scoped(w, r)` and pass the `cfg` loaded by `providerEntries` out instead of re-loading — contract-risk: wire (scoping semantics of the route)
- [design-5] P2 internal/tui/app.go:133-135 — `connLostMsg` only clears `store.Conn`; there is no REST re-hydration when the SSE stream drops and the client's backoff loop reconnects, so every event missed in the outage window is lost from the store forever (the bus overflow drop — the realistic in-process trigger — happens exactly when the store is most stale; the first `EventMsg` after reconnect flips `Conn` back to true with no reconciliation). — fix: return `a.hydrateCmd()` from the `connLostMsg` case (or on the first `EventMsg` after a loss) so the current route re-hydrates — contract-risk: behavior (TUI state after reconnect)
- [design-6] P3 internal/server/handlers_session.go:55-75 — `scopedSession` already fetches the row via `s.DB.GetSession(id)` but returns only the id, so every caller re-fetches the session a second time (`handleSessionGet` :144, `handleSessionPatch` :184, `handleSessionDelete` :197) and `handleCommand` resolves the scope twice (:329 via scopedSession, :350 via `s.scoped`); the re-read also conceals the row behind a second TOCTOU lookup. — fix: `scopedSession(w, r) (storage.SessionRow, bool)` so callers use the already-fetched row; `handleCommand` resolves scope once — contract-risk: none — status: FIXED ed51579 (row returned; GET/DELETE build response/event from row+ListMessages, COMMAND uses row.ProjectDir; PATCH keeps its one post-update re-read, which the response state requires)
- [design-7] P3 internal/server/handlers_misc.go:210-227 vs 246-285, 368-371 — duplicated read-merge-write of a yolo.jsonc layer: `writeProjectLayer` is the project-dir helper (returning only error) while `handleGlobalConfigPatch` inlines the same ReadFile→UnmarshalJSONC→Merge→MarshalIndent→WriteFile sequence with its own per-step `fail` calls, and `handlePermissionList` builds a `seen` map (:368-371) that is never read. — fix: one helper `mergeWriteConfig(path string, partial map[string]any, ensureDir bool) (map[string]any, error)` used by both routes; delete `seen` — contract-risk: none — status: FIXED ed51579 (helper shared by both PATCH routes, writeProjectLayer and the dead seen map removed; responses wire-identical)
- [design-8] P3 internal/server/handlers_session.go:367-373 — `emit` silently drops `protocol.MakeEvent` marshal failures: a non-marshalable props value would be an invariant violation for our own wire DTOs and vanishes with no log line (the server has a logger and a 5xx log path for everything else). — fix: `s.Log.Errorf("emit %s: %v", t, err)` before the drop — contract-risk: none — status: FIXED ed51579 (exactly as specified; nil logger stays a no-op)
- [design-9] P3 internal/tui/app.go:61-62,737-746,68-88 — production `App` carries its test surface: exported `Cmds []tea.Cmd` capture field plus `record` flag (set only in _test.go), and `NewApp(c, s *store.Store, ...)` takes a store pointer then immediately copies it by value (`a.store = *s`) — main.go:273 passes an empty `&store.Store{}`, so the pointer API suggests shared ownership the semantics (snapshot) doesn't deliver. — fix: move the record/Cmds hook to a test-only wrapper in _test.go; take the store by value (`NewApp(c *client.Client, s store.Store, ...)`), deleting the vestigial empty-store argument site — contract-risk: none — status: FIXED 3632e98 (store by value at all 10 call sites incl. main.go; record/Cmds gone from App, capture lives in rec_test.go recApp over an unexported emitSink)
