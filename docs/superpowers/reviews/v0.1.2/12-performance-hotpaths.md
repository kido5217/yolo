## Findings

- [performance-1] P2 internal/session/engine.go:686 (saveDelta; also startPart/finalizePart 703,720) + internal/storage/dao.go:231 (UpsertPart) + :299 (ProtocolToPart) — every streamed delta re-encodes the ENTIRE accumulated part text (json.Marshal of map{"text": fullText}, 8 allocs) and re-writes the whole state_json row to SQLite: O(n²) bytes per part on the turn goroutine's critical path. Evidence (scratch benchmarks, Ryzen 5800X3D, Go 1.26.6): ProtocolToPart text 64KB = 138µs/171KB, 128KB = 239µs/307KB (~1.6-1.9 ns/byte, escaping-dominated, unavoidable); real UpsertPart (verbatim SQL, modernc.org/sqlite, 64KB state_json) = 210-215µs/call, 14 allocs; a 64KB part streamed 1KB-delta-wise costs 12.9ms cumulative DB writes (128KB part ≈ 51ms); a 128KB text part thus burns ~13ms encode + ~51ms persist spread over its stream. — fix (0.2.0): persist full text at part finalization (+ an occasional checkpoint if crash-recovery needs it), keep per-delta events for the wire only; or a delta-incremental storage layout. — contract-risk: behavior
- [performance-2] P3 internal/storage/dao.go:313-321 (ProtocolToPart text branch) — map[string]any + encoding/json reflection/marshal for a fixed 3-key document; the fix removes map boxing, key marshaling and buffer-growth reallocs but NOT the string escaping pass. Evidence: byte-identical hand-rolled encoder (verified equal output incl. key order end/synthetic/text and HTML escaping, TestProtocolToPartFast_Identical PASS): 128KB 219.9µs/3 allocs vs 239.4µs/8 allocs (−8%), 64KB 133.8µs vs 138.2µs (−3%), 1KB 6.5µs/3 vs 4.9µs/8. — fix: append `{"end":N,"synthetic":true,` prefix + json.Marshal(p.Text) into a pre-grown strings.Writer; keep map-marshal for the tool branch. — contract-risk: none
