## Findings
- [safety-1] P0 internal/tool/bash.go:63 — `bashPrefix` panics (index out of range) on whitespace-only commands: `bashArgs` (bash.go:77) rejects only `""`, so `command: "   "` passes; `strings.Fields("   ")` is an empty slice and `tokens[0]` panics. The engine contract (tool.go:64-70) calls `Patterns(raw)` before the permission check, so the panic lands on the engine's live tool-execution path and crashes the process (server+TUI) unless an upstream caller recovers. Verified in isolation. Upstream uses tree-sitter pattern extraction (out of scope per the v1 pin at bash.go:42-45), so the panic is port-introduced — the pinned first-token simplification was never made safe. — fix: reject in `bashArgs` (`if strings.TrimSpace(v) == "" { err = errors.New("command is required") }`, reusing the existing error path) or guard `len(tokens) == 0` in `bashPrefix` — contract-risk: none
- [safety-2] P0 internal/tool/read.go:227,296 — model-controlled `offset`/`limit` reach allocation and slice arithmetic with only a non-negative-integer check (`argInt`, read.go:109-115): (a) `readLines` preallocates `make([]string, 0, limit)` — `limit: 9000000000000000000` panics `makeslice: cap out of range` (verified), and values ≥ ~1e9 already attempt 16GB+ contiguous preallocation; (b) `readDirListing` computes `end := start + limit`, which overflows int64 for huge offset/limit → negative `end` → `names[start:end]` panics `slice bounds out of range` (verified). Upstream read.ts:269 (JS float arithmetic, `slice` clamps) and read.ts:137 (no preallocation) handle any limit gracefully — port-introduced. — fix: bound the preallocation only (e.g. `cap := limit; if cap > 8192 { cap = 8192 }; raw := make([]string, 0, cap)` — do NOT clamp `limit` itself, that changes line-count semantics) and make the listing clamp overflow-safe (`if end < 0 || end > len(names) { end = len(names) }`) — contract-risk: none
- [safety-3] P1 internal/tool/bash.go:83-90 — `timeout: 0` from the model disables the kill timer (shell.go:84: `timeoutMS <= 0`), so a hung command (`sleep infinity`) runs unbounded and blocks the session round until manual abort. Upstream validates the bash `timeout` as `Schema.optional(PositiveInt)` (tool/shell/prompt.ts:18), so 0 is rejected upstream — the port's `argInt` non-negative check silently diverges, and the on-line-86 error message ("timeout must be a positive integer") already documents the intended contract. — fix: in `bashArgs` reject `n <= 0` (error fires, message becomes accurate) — contract-risk: behavior
- [safety-4] P2 internal/tool/shell.go:130-136 — the `!ok || ev.last` branch (shell process EOFed without emitting its marker) returns a *successful* Output with partial output and `Meta{"exit": -1}`, so the model is told a command that never completed succeeded. Normal completion always returns via the marker match first, so reaching this branch means the process died mid-command — an error surface, not a success. — fix: on `ev.last`/closed-without-marker return an error (e.g. `errors.New("shell process exited before command completion")`) instead of `(code, buf.String(), nil)` — contract-risk: behavior
- [safety-5] P3 internal/tool/grep.go:189-193 — `_ = filepath.WalkDir(...)` discards walk-level errors (glob.go:141-143 correctly returns its `werr`): a root-level walk failure (search dir removed mid-walk, permission error on a non-skipped root) silently degrades to `Text: "No files found"` instead of an error. Per-entry errors are intentionally swallowed (skip unreadable files), but the root error is load-bearing. — fix: capture the return; if `werr != nil && len(matches) == 0` return the error (or always return it when `werr != nil` and no matches were seen) — contract-risk: none
- [safety-6] P3 internal/tool/edit.go:118 — bare type assertion `m := v.(*sync.Mutex)` in `fileLock`; the `editLocks` sync.Map is only ever written by this function so the invariant holds today, but the skill's safe-assertion rule says comma-ok regardless (a future second writer of the map would turn this into a latent panic). — fix: `m, _ := v.(*sync.Mutex)` — contract-risk: none
