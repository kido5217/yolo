> chain — claim the bead at task start, close it at task end).

**Goal:** the `/` slash menu becomes the pixel-faithful port of upstream v1.18.18
autocomplete (spec §1): a bordered dropdown anchored above the input (theme-token
chrome, `primary`-bg selection row), fuzzy + frecency ranking (cap 10, no scroll),
keyboard (up/down wrap, `enter` runs, `tab` completes, `esc` clears) and mouse
(hover moves selection, click runs) parity, the context-aware home hint row, the
`No matching items` empty text, and the `DEVIATIONS.md` entries + re-baselines.
No new dependencies; zero telemetry; the `@`-picker and the palette are out of
scope (sibling epics build on this epic's `dropdown.go`).

**Architecture:** a shared primitive `internal/tui/dropdown.go` (S1) renders a
bordered row list — split left/right `theme.border` border (no top/bottom edges),
`backgroundMenu` inner fill, `primary`/`selectedForeground` selection row,
`text`/`textMuted` rows, width = the prompt-box width, height = `min(10, count,
space-above)`, no scroll — plus a cell→row hit-test. The slash menu rewires onto
it (S2: `menuView`'s two-column rows inside the box; the `@`-picker's `acView`
stays). The anchors move the menu from the 0.8.0 left-overlay rows to above the
input (S3: home — above the box top edge at `boxL`/`boxW`, logo overlaid while
open; session — above the prompt line, overlaying the transcript tail, viewport
keeps full height). Command-name frecency (S4) mirrors the file-path frecency:
a `command_frecency` KV key in the same theme KV as `prompt_frecency`, the
`freq/(1+age_days)` score, rank = fuzzy ×(2 if prefix) ×(1 + commandFrecency),
threshold 0, cap 10, empty query = the full list frecency-ranked, touch on
slash-menu execution. Mouse (S5): `tea.WithMouseCellMotion` on the Program
options (main.go:768) + a `tea.MouseMsg` case routed to the dropdown while the
slash menu is open (hover = move selection, click = run). Keys (S6): `tab`
intercepted in the menu path before `handleAppKeys` (complete `/name ` + close,
no run; closed-menu `tab` still cycles the agent), `shift+tab`/`esc` unchanged
(esc clears the whole input — parity, kept), query change resets `sel` to 0, and
the home hint's first segment goes context-aware (`tab complete` / `tab agents`).
S7 lands the `No matching items` text, the §5 re-baselines, the second home
mock, and the four `DEVIATIONS.md` entries last.

**Tech Stack:** Go 1.26 (module requires ≥ 1.25). Allowlist runtime deps
UNCHANGED — the primitive is pure `charm.land/lipgloss/v2` (v2.0.6) + stdlib;
no new deps, no `go get`/`go mod tidy`. Frecency reuses the existing
`engine.KV()` store surface (the `prompt_frecency` idiom, app.go:580); fuzzy
ranking reuses `github.com/sahilm/fuzzy` (v0.1.3, the mention.go idiom). Test
idioms: the teatest v2 suites (`teatest.NewTestModel`, `tm.Send` takes
`tea.Msg` directly — a `tea.MouseMsg` leg rides on it; the `keyMsg`/`typeIn`
helpers, app_test.go:102-114), the whitebox unit render pins (render-to-string
+ SGR/substring assertions, the `testApp` harness), and the existing
`TestPromptMenu*` legs (prompt_test.go). The `cmd/yolo/main.go`
Program-options change is the one non-TUI edit.

## Global Constraints

- **The gate (run at module root after every task):** `go vet ./... && go test
  ./...` green + `gofmt -l .` prints nothing (Go 1.26 toolchain). Every task
  ends gate-green with ONE commit carrying the plan-pinned message.
- **Never commit to `main`** (user directive): work lands on
  `plan/menu-parity-0.10.0` (checked out; based on latest main @ `78d518a`),
  one task at a time. Checkpoint commits between tasks: `docs: checkpoint —
  Task N (<name>) done, next is Task N+1 (<name>)`.
- **Beads:** claim the task bead before starting
  (`bd update yolo-asg --claim --json`); close it after the commit
  (`bd close yolo-asg --reason "Task 1 done" --json`). Do NOT close
  `yolo-2vt` (the epic closes at its own closeout). The linear `blocks` chain
  means `bd ready` shows exactly the current task.
- **5-step TDD per task** (docs/superpowers/AGENTS.md): failing test →
  confirm FAIL (the failure must be the asserted one, not a compile error) →
  minimal implementation → gate green → commit with the pinned message.
- **No new dependencies.** No `go get` / `go mod tidy` — the allowlist is
  unchanged; every import this plan adds is stdlib or an existing allowlisted
  module (lipgloss v2, bubbletea v2, the `engine.KV()` surface, sahilm/fuzzy).
- **Tests never hit the network.** TUI legs are whitebox unit + teatest
  against the dead-port app (`testApp`, or `testutil.Boot` localhost
  in-process — the established idiom, no external network).
- **Zero telemetry (root principle 1):** the command-name frecency is
  TUI-local (the same theme KV as `prompt_frecency`); the dropdown/mouse/key
  work is pure client; no OTEL/usage surface is touched.
- **TUI import purity (root principle 4, enforced by `TestImportsDirection`):**
  non-test files under `internal/tui/` import only `internal/protocol` +
  `internal/tui/*` (+ stdlib/charm deps). The `cmd/yolo/main.go` mouse-option
  change is outside the purity rule (cmd is exempt).
- **Deviation handling:** the four spec §4.1 entries land at the next-free
  numbers (planned 308-311; the verified tail at plan time is 307 — re-verify
  the tail at S7). Only Task 7 adds entries; the intermediate tasks must NOT
  add entries.
- **Pins (root principle 3):** the four sha256-pinned tests
  (`TestLogoBlockPinned`/`TestTipsPinned`/`TestDescPinned`/
  `TestParityFixturesPinned`) are NOT re-baselined by this work — S7 verifies
  they stay green.
- **Skills:** `golang-naming` + `golang-code-style` always paired on new code;
  `golang-testing` for the test legs; the `charm-stack` skill for the
  Bubbletea/Lipgloss work.
- **Subagents (root principles 7-8):** at most one at a time; a YOLO root
  spawns only YOLO subagents.
