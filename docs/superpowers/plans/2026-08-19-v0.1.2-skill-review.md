# Yolo v0.1.2 — Skill-Driven Code Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Review the released v0.1.1 codebase with each of the 15 pinned golang skills as a review lens (15 sequential waves, severity order), fix behavior-neutral findings, and ship a hardened codebase plus a populated 0.2.0 defer log.

**Architecture:** 16 tasks = wave 0 (context + inventory) + 15 skill waves + roll-up. Each skill wave: scoped review subagents (dispatched one at a time — see Global Constraints — one per chunk, each ≤ ~6k LOC in scope) write one findings file each; one fix subagent (policy B: fix only `contract-risk: none` findings, TDD for bugs) applies fixes; full gate; checkpoint commit. The orchestrator session never reads source or findings bodies — small-context discipline.

**Tech Stack:** Go ≥ 1.25 (installed 1.26.5), pinned deps only (no new deps allowed), golangci-lint (v2 config), the 15 skills in `.agents/skills/`.

**Spec:** `docs/superpowers/specs/2026-08-19-v0.1.2-skill-review-design.md`

## Global Constraints

- **Branch:** `v0.1.2_skills_review` (already exists, base `1784ac0`). All work commits here.
- **Gate (must pass before EVERY commit):** `go vet ./... && go test ./...` · `gofmt -l .` prints nothing (Go 1.26 formatter; if it prints files, run `gofmt -w` on them, re-run gate) · `golangci-lint run ./...` clean.
- **Zero new dependencies.** Never modify `go.mod`/`go.sum` except wave 13 if a benchmark needs an existing test dep — it does not; do not touch them.
- **Never modify:** the 14 sha256-pinned prompt files (`internal/session/prompt/*.txt`), tool `desc/*.txt` files, golden fixtures (`internal/server/testdata/golden/`), `skills-lock.json`, the skill files in `.agents/skills/`.
- **Faithful port:** do not re-derive upstream v1.18.18 design choices; the invariants in `CONTEXT.md` (written in Task 0) are binding for every subagent.
- **Orchestrator discipline (the executor session):** never read source files or findings-file bodies. Allowed reads: `git log/status/diff --stat`, `wc -l`/file lists, findings-file `Stats` + `COVERAGE` lines (grep only), this plan's current task slice, `PROGRESS.md`. All heavy reading happens in subagents.
- **Stop-the-line (spec §5 false-positive guard):** after any fix wave, if >50% of that wave's findings are rejected (final status `FALSE` + `WONTFIX`), STOP — do not dispatch the next wave; ask the user (possible lens misapplication).
- **Subagent dispatch:** via the `task` tool, `subagent_type: "general"`. **Subagents one at a time** (user constraint 2026-08-20; supersedes the earlier "≤3 concurrent" wording): issue exactly one subagent, wait for its full return, then dispatch the next in the wave's chunk order. Fix subagent: always alone. A subagent that returns without its findings file → re-dispatch once (prompt is idempotent), then mark the chunk `COVERAGE: skipped` in a one-line findings file with the Stats line `P0:0 P1:0 P2:0 P3:0` and continue.
- **Commits:** findings commit per wave, conventional fix commits, checkpoint commit per wave — exact messages are in each task. Update `PROGRESS.md` at every checkpoint (keep the file small, per its own header rules).
- **Tag `v0.1.2` only with explicit user go-ahead.** PR to `main` is prepared in Task 16; merge is user-decided.

## Resume Protocol (every execution session)

1. Read `docs/superpowers/PROGRESS.md` → "Active" section → current wave number W.
2. Read this plan's Task W slice in full (only that task).
3. Inspect state: `git log --oneline -5`, `ls docs/superpowers/reviews/v0.1.2/`, `grep -E '^(## Stats|COVERAGE)' docs/superpowers/reviews/v0.1.2/<this wave's files>`; resume at the first uncompleted step of Task W (checkboxes are the source of truth for what's done).
4. Never re-run a step whose commit already exists.

Task 1's three prompts are fully filled (dispatch them verbatim). Waves 2–15 give all substitution values per chunk, so composing a prompt is mechanical with no decisions left to the executor. (This replaces verbatim repetition of the boilerplate for 30+ prompts — see Plan Note 5.)

```

<FILES>

   - read-heavy: read the scoped files in full.
   - grep-driven: grep for your skill's patterns first, read only files with hits in full.
   - script-driven: run the scan commands given in your task scope, read only hit files.

# v0.1.2 Review Context — invariants (do NOT flag these)

Repo: /home/kido/network/projects/yolo · module github.com/kido5217/yolo · Go ≥ 1.25 (installed 1.26.5).
Upstream: faithful port of anomalyco/opencode v1.18.18 (read-only reference clone: /tmp/opencode-upstream).
Gate (must pass before every commit): `go vet ./... && go test ./...` · `gofmt -l .` prints nothing (Go 1.26) · `golangci-lint run ./...` clean.

## Hard invariants (flagging any of these is a misfire)
1. Zero telemetry is a permanent project principle. OTEL/OTLP exporter, OTel spans on LLM
   calls, and the telemetry-identity field are intentionally ABSENT; `OTEL_*` env vars are
   inert; the ported config schema deliberately omits `experimental.openTelemetry`.
2. Single deliberate wire deviation: scoping header `x-yolo-directory` (upstream:
   `x-opencode-directory`). All other REST paths / JSON shapes and the legacy SSE event
   set mirror upstream verbatim.
3. Verbatim pins, sha256-guarded by tests: the 14 session prompt files
   (`internal/session/prompt/*.txt`) and every tool `desc/*.txt` file. Never reword.
   Golden fixtures (`internal/server/testdata/golden/`) regenerate only via the contract
   suite's `-update` flag.
4. TUI import rule: non-test files under `internal/tui/` import only `internal/protocol`
   + `internal/tui/*` (+ stdlib + charm deps). `_test.go` may import
   `internal/server/testutil` (deliberate escape hatch). Guarded by
   `internal/tui/imports_test.go`.
5. Host toolchain quirk: plain `import "embed"` + a scalar `//go:embed` fails typecheck
   on both installed toolchains; the `import _ "embed"` workaround (internal/tool/
   read.go, write.go, edit.go) is intentional.
6. Tests never hit the network. `YOLO_LLM=fake` (+ `YOLO_FAKE_SCRIPT`) selects the
   scripted fake driver (`internal/llm/fake`). `scripts/e2e-live.sh` is user-run only,
   never CI.
7. Provider catalog is built ONCE at server startup from the startup-dir config; per-turn
   config does not change BaseURL. `KIDO_BASE_URL` is honored by the e2e script (it
   writes config), not by yolo.

## Faithful-behavior pins (upstream-mirrored; not findings)
- SSE ordering: user message + part events are published BEFORE the busy
  `session.status` (upstream prompt.ts parity; deviation 41).
- Doom loop: sliding window of 3 identical calls; wildcard `*`-deny hides a tool iff the
  last matching rule is a `*` deny; `write`+`edit` both map to permission `edit`.
- `/quit` is the canonical exit slash command; `/exit` is an accepted alias on every
  surface (deviation 66).
- TUI keymap: pgup/pgdn scroll, `\`+enter newline. JSONC comments are NOT preserved on
  config PATCH rewrite (v1 behavior pin).
- `POST /session/{id}/abort` blocks until engine idle (≤2s, 10ms poll) before 200
  (deviation 33).
- Tool Part ID == model call ID; CallID is not persisted elsewhere in schema v1
  (deviations 20/23).
- Engine continues a round when finish == "tool_calls" OR the round emitted any tool
  part (robustness rule, deviation 21e); max 50 rounds.

## Meta-rule
Flag the port's INTERNAL correctness and idiomaticity: races, leaks, nil-safety, error
flow, resource lifecycle, test quality, naming, style. Do not re-derive upstream v1.18.18
design choices. If a behavior diff from upstream looks suspect, compare
/tmp/opencode-upstream (read-only) before flagging, or mark the finding
"needs-upstream-check".
```
